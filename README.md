# Gorkha Earthquake Damage Prediction

## 1. Project Overview

This project uses building survey records from the 2015 Gorkha earthquake in Nepal to predict three recorded damage grades. It compares Logistic Regression, Random Forest, and CatBoost with a baseline that always predicts the most common grade.

The project was developed for the CSC61304 Machine Learning and Intelligent Systems individual assignment. The [notebook](earthquake_damage_prediction.ipynb) contains the analysis, model training, evaluation, and export.

## 2. Project Objectives

- Check the survey data and explore how damage varies with building characteristics and location.
- Clean the records, create building features, and prepare them for training and testing.
- Compare three classifiers with a majority-class baseline and tune each classifier using training data.
- Evaluate the models overall and by damage grade, including how far wrong predictions are from the recorded grades.
- Propose an inspection-support system with engineer review, feedback, and safeguards for future updates.

## 3. Dataset Information

The data come from DrivenData’s [Richter's Predictor competition](https://www.drivendata.org/competitions/57/nepal-earthquake/data/). Each row represents one surveyed building. The combined dataset contains **260,601 labelled buildings** and **40 columns**, including 38 predictors, the building ID, and the target.

| Field or group | What it describes |
| --- | --- |
| `building_id` | Survey record identifier. It is excluded from the model inputs. |
| `damage_grade` | Recorded damage, from grade 1 (low) to grade 3 (almost complete destruction). |
| Geographic IDs | Three coded geographic levels. |
| Building measurements | Age, floor count, and relative height and area. |
| Construction and use | Foundation, roof, materials, occupancy, and use indicators. |

The initial checks found zero missing values, duplicate rows, or duplicate building IDs. The notebook treats the recorded age of `995` as a placeholder in 1,390 records and flags it before replacing the age.

## 5. Exploratory Data Analysis

The notebook compares damage grades across building ages, floor counts, foundation and roof categories, construction materials, and geographic areas. It also checks unusual values and looks at correlations among selected inputs.

Grade 2 accounts for about **56.9%** of buildings, followed by grade 3 at **33.5%** and grade 1 at **9.6%**. The imbalance is why the results include macro F1 and scores for each grade alongside accuracy.

## 6. Data Preprocessing and Feature Engineering

The notebook drops the building ID, flags placeholder ages, and creates features such as material counts, height per floor, and an approximate volume measure. The shared pipeline fills missing numeric values with training medians, scales numeric inputs, one-hot encodes categories, and removes selected inputs with very low variance. It uses cross-fitted target encoding for the three geographic IDs, so a training record's own grade does not contribute to its encoded value.

The 80/20 stratified split keeps similar grade proportions in the **208,480 training buildings** and **52,121 test buildings**. The preprocessing pipeline is fitted within each training fold during cross-validation.

## 7. Models and Hyperparameter Tuning

| Model | Role | Search method | Selected settings |
| --- | --- | --- | --- |
| Majority-class baseline | Predicts the most common training grade, grade 2. | No tuning | Most frequent class |
| Logistic Regression | Provides a linear comparison. | Grid search, 8 configurations | `C=1.0`, no class weights |
| Random Forest | Averages predictions from multiple trees. | Random search, 15 configurations | 200 trees, maximum depth 20, minimum leaf size 4, square-root feature sampling, no class weights |
| CatBoost | Trains trees in sequence to improve predictions. | Random search, 12 configurations | 800 iterations, learning rate 0.03, depth 10, L2 leaf regularisation 5, random strength 2, bagging temperature 0.5 |

Tuning uses three-fold stratified cross-validation on the same 60,000-building training sample. Micro F1 is the main tuning metric because DrivenData uses it for this task. The notebook refits each selected configuration on the full training set before evaluating it on the test set.

## 8. Model Evaluation

Micro F1 equals accuracy here because each building receives one predicted grade. Macro F1 gives each grade equal weight. Quadratic weighted kappa accounts for the distance between grades, and macro ROC AUC measures how well the model ranks buildings for each grade using its predicted probabilities.

| Model | Test accuracy / micro F1 | Macro F1 | Weighted F1 | Quadratic kappa | Macro ROC AUC |
| --- | ---: | ---: | ---: | ---: | ---: |
| Majority-class baseline | 56.89% | 0.2417 | 0.4126 | 0.0000 | 0.5000 |
| Logistic Regression | 73.94% | 0.6763 | 0.7331 | 0.5994 | 0.8690 |
| Random Forest | **75.13%** | 0.6981 | **0.7458** | 0.6210 | 0.8814 |
| CatBoost | 74.99% | **0.6997** | 0.7449 | **0.6220** | **0.8816** |

The notebook exports Random Forest because it had the highest test accuracy. CatBoost had the highest macro F1. Random Forest correctly identified **63.92%** of severely damaged buildings, which shows why the overall accuracy is only part of the comparison.

The study uses test accuracy to choose the exported model, and the training and test sets overlap geographically. The scores are an internal benchmark for buildings from the historical survey. An evaluation that holds back entire areas would help assess how well the model transfers. The probabilities still need calibration.

## 9. Proposed Intelligent System

The proposed service would collect and validate building records, estimate probabilities for all three grades, and flag uncertain or high-risk cases for engineers. It would keep inspection outcomes as feedback for future updates. Retraining would take place offline, with validation and approval before replacing the active model.

The notebook implements data preparation, training, scoring, and model export. The survey form, review queue, and feedback process are at the design stage.

## 10. Ethical Considerations

An underestimated damage grade could delay inspection of a severely damaged building. The service would help engineers prioritise cases, with a qualified reviewer responsible for consequential decisions. A live service would also need to check performance by area and construction type, limit access to household records, and record the model version and any changes made by an engineer.

## 11. Running the Project

Start in the repository folder with Python 3.13 available. The commands below are for Windows PowerShell.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

1. Sign in to [DrivenData](https://www.drivendata.org/competitions/57/nepal-earthquake/data/), join the competition, and accept its terms.
2. Download `train_values.csv` and `train_labels.csv` and place them beside the notebook. If you keep them elsewhere, set the `DATA_DIR` environment variable before starting Jupyter. The notebook builds `earthquake_train_combined.csv` automatically if needed.
3. Open the notebook in VS Code, select the environment created above, and run all cells. To run from PowerShell, use the command below.

```powershell
.\.venv\Scripts\python.exe -m jupyter nbconvert --to notebook --execute --inplace --ExecutePreprocessor.timeout=-1 earthquake_damage_prediction.ipynb
```

A full run took about 30–40 minutes in the project environment. It refreshes the notebook's saved outputs and regenerates plots and result files.
